### 修掉的坑
- **`VmService.maybeAutoRestart` 里不能调 `runner.stop()`**：进程已自己退出、`QemuRunner.process` 已置空，再 stop 会让旧 `start()` 协程的 `waitFor()` 返回并二次上报状态，触发新一轮 Error 吃掉重试计数。只调 `runner.start()`。
- **`startsWith("已")` 判断操作成功**在英文文案下永远判失败 → `ComposeScreen` / `PortForwardDialog` / `ContainerDetailScreen` 全改成独立布尔状态。

### R8 / 构建（重要）
这台机器只有 **7.9 GB 内存、空闲 0.2 GB**，release 的 R8 三次被杀：
1. `-keep class androidx.compose.** { *; }` 让 `seeds.txt` 涨到 **14 MB**（material-icons-extended 上千图标全保留），optimizer 跑 38 分钟不出包。**这条规则完全不需要**，Compose 各库自带 consumer rules。删掉后 seeds 降到 779 KB。
2. 内存预算：原 `-Xmx4096m` + `kotlin.daemon.jvmargs=-Xmx2048m` ≈ 6 GB → 改 `-Xmx2560m` / `1536m`，并加 `org.gradle.workers.max=2`。
3. 即便如此，R8 仍在 optimizer 阶段被系统直接杀掉（**无 hs_err、进程凭空消失**，daemon 日志停在 `ExecuteBuild`）。最终加 **`-dontoptimize`**：保留 tree-shaking + 混淆（dex 体积的主要来源），跳过优化 pass。

> 换到内存宽裕的机器可以删掉 `proguard-rules.pro` 里的 `-dontoptimize`。

### 排障经验

### 真机验证发现的 2 个 bug（已修）
1. **启动阶段文案不跟随应用语言**：`VmManager` / `VmService` 用 Application/Service context 调 `getString`，其 configuration 跟随**系统**语言；应用内语言覆盖只套在 Activity 上。修法：两者都加 `private val i18n get() = LocaleHelper.wrap(this)`，所有取串走它。
2. **底栏英文标签断词**：6 个页签在 393dp 屏每项约 65dp，扣内边距只剩 ~43dp。11sp 断成 "Contain/ers"，写死 10sp 又截成 "Containe"。修法：`NavLabel` 用 `BoxWithConstraints` + `rememberTextMeasurer()` 从 11sp 逐 0.5sp 降到 8sp，取第一个放得下的。

### 其他验证结论
- 切语言后 `rememberSaveable` 保住了当前页签（原来会跳回首页）。
- 更新检测实测：仓库最新 v0.4.2 < 本地 0.5.0 → 正确提示 "You are on the latest version"。
- R8 混淆后的 release 包端到端跑通：下载底座 → VM Ready（podman 5.2.5 / arm64）→ `podman run --rm alpine echo hello-v050` 输出成功。

- `VmBundle.BUNDLE_VERSION = "0.1.0"` 是常量、与 App 版本号无关，所以升级 App 不会强制重下底座；同签名可直接 `install -r` 覆盖。
