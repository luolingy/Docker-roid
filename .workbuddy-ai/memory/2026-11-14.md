### 修掉的坑
- **`VmService.maybeAutoRestart` 里不能调 `runner.stop()`**：进程已自己退出、`QemuRunner.process` 已置空，再 stop 会让旧 `start()` 协程的 `waitFor()` 返回并二次上报状态，触发新一轮 Error 吃掉重试计数。只调 `runner.start()`。
- **`startsWith("已")` 判断操作成功**在英文文案下永远判失败 → `ComposeScreen` / `PortForwardDialog` / `ContainerDetailScreen` 全改成独立布尔状态。

### R8 / 构建（重要）
这台机器只有 **7.9 GB 内存、空闲 0.2 GB**，release 的 R8 三次被杀：
1. `-keep class androidx.compose.** { *; }` 让 `seeds.txt` 涨到 **14 MB**（material-icons-extended 上千图标全保留），optimizer 跑 38 分钟不出包。**这条规则完全不需要**，Compose 各库自带 consumer rules。删掉后 seeds 降到 779 KB。
2. 内存预算：原 `-Xmx4096m` + `kotlin.daemon.jvmargs=-Xmx2048m` ≈ 6 GB → 改 `-Xmx2560m` / `1536m`，并加 `org.gradle.workers.max=2`。
3. 即便如此，R8 仍在 optimizer 阶段被系统直接杀掉（**无 hs_err、进程凭空消失**，daemon 日志停在 `ExecuteBuild`）。最终加 **`-dontoptimize`**：保留 tree-shaking + 混淆（dex 体积的主要来源），跳过优化 pass。

> 换到内存宽裕的机器可以删掉 `proguard-rules.pro` 里的 `-dontoptimize`。

### 排障经验

### 真机验证发现的 2 个 bug（已修）
1. **启动阶段文案不跟随应用语言**：`VmManager` / `VmService` 用 Application/Service context 调 `getString`，其 configuration 跟随**系统**语言；应用内语言覆盖只套在 Activity 上。修法：两者都加 `private val i18n get() = LocaleHelper.wrap(this)`，所有取串走它。
2. **底栏英文标签断词**：6 个页签在 393dp 屏每项约 65dp，扣内边距只剩 ~43dp。11sp 断成 "Contain/ers"，写死 10sp 又截成 "Containe"。修法：`NavLabel` 用 `BoxWithConstraints` + `rememberTextMeasurer()` 从 11sp 逐 0.5sp 降到 8sp，取第一个放得下的。

### 其他验证结论
- 切语言后 `rememberSaveable` 保住了当前页签（原来会跳回首页）。
- 更新检测实测：仓库最新 v0.4.2 < 本地 0.5.0 → 正确提示 "You are on the latest version"。
- R8 混淆后的 release 包端到端跑通：下载底座 → VM Ready（podman 5.2.5 / arm64）→ `podman run --rm alpine echo hello-v050` 输出成功。
- **MIUI 最近任务卡片用 `adb shell input swipe` 划不掉**（手势被卡片内容滚动吃掉），"划卡后容器是否继续跑"没做成真机验证。
- 崩溃自重启无触发入口，仅代码验证。
- `VmBundle.BUNDLE_VERSION = "0.1.0"` 是常量、与 App 版本号无关，所以升级 App 不会强制重下底座；同签名可直接 `install -r` 覆盖。


## v0.6.0：暗色模式 + 项目更名 Podroid（15:00–16:00）

**改名范围**：包名 `com.midsancode.docklet` → `com.midsancode.podroid`（手机上算全新应用，旧 Docklet 需手动卸载，88MB 底座与容器数据不迁移）；GitHub 仓库 `luolingy/Docklet` → `luolingy/Podroid`（`gh api -X PATCH repos/... -f name=Podroid`，**改名后 release 资产和旧 URL 重定向都保留**，v0.4.2 的 Image/rootfs/qemu-bundle 仍可下）。
- 61 个文件批量替换 `docklet→podroid` / `Docklet→Podroid` / `DOCKLET→PODROID`，外加 `DockletApp.kt`→`PodroidApp.kt` 等 4 个文件改名、目录 `com/midsancode/docklet/`→`podroid/`（`git mv` 保留历史）。
- **签名 JKS 内部别名不会跟着文件名变**：`keystore.properties` 改了口令和 storeFile，但 JKS 里别名还是 `docklet` → 签名会失败。必须 `keytool -changealias -alias docklet -destalias podroid` + `keytool -storepasswd`。改完证书 SHA-256 不变。
- **`DESIGN.md` 里的 "Podroid" 原指第三方项目 `ExTV/Podroid`**，全局替换把两个 Podroid 混成一句。已 `git checkout` 还原，只在开头加更名说明并注明区分。
- `settings.gradle.kts` 的 `rootProject.name = "DockerDroid"` 不含 docklet 字样，正则漏掉，需单独改。

**暗色模式**：三态 `system/light/dark` 存 DataStore（`themeMode`），`MainActivity` 解析后传 `PodroidTheme(darkTheme=)`。
- **`LocalDarkTheme`（staticCompositionLocalOf）** 是关键：不能再用 `isSystemInDarkTheme()`，否则用户手动选深色而系统是浅色时，`toneColors()` 语义色仍返回浅色版。
- `values-night/colors.xml` + `values-night/themes.xml` 做冷启动窗口底色；浅色主题基类从 `Theme.Material` 换成 `Theme.Material.Light.NoActionBar`，否则冷启动先黑一帧。
- 只有 `TerminalScreen` 保留硬编码深色（终端本就该恒深），其余全走主题 token。

**真机验证（192.168.1.11，debug 包）**：
- 设置页明暗三芯片切换即时生效；深/浅两套下主页、容器、镜像、资源、终端、设置六页均无对比度事故。
- 底座下载走 `ghfast.top`/`gh-proxy.com` 前缀，新仓库名下 88MB 完整落地（Image 43.5MB + rootfs 44.9MB）。

## v0.6.0 发布收尾

- **release 已上线**：`https://github.com/luolingy/Podroid/releases/tag/v0.6.0`，资产 = `app-release.apk`(27.9MB) + `Image` + `rootfs.squashfs` + `qemu-bundle.tar.gz`。
- **签名密钥库重建**：`changealias` 只改别名，证书主体 DN 仍是 `CN=Docklet`（apksigner 能看出来）。趁 `com.midsancode.podroid` 还没发过版，直接 `keytool -genkeypair -dname "CN=Podroid,..."` 重建了整个 JKS，新指纹 `6A:D3:4E:4D:…:04:FA`。旧库备份在 `.work/podroid-release.jks.docklet-cn.bak`。因为包名已变，与旧 Docklet 不构成升级关系，换签名无副作用。
- **设计缺陷（重要）**：`Mirrors.RELEASE` 用 `releases/latest/download/<asset>` 取底座，意味着**每个 App release 都必须重传 121 MB 底座资产**，否则新版本一发布，`latest` 指向它、底座就下不到。本次已把三件套重传到 v0.6.0。根治办法是把 URL 钉到固定 tag（如 `releases/download/v0.4.2/`）或建一个专用 `bundle` release，但需要改常量重新构建。
- 构建耗时：全量 29m50s（本机内存压力，比常规 10~15 分钟慢一倍）；只改签名配置时增量重打包 11m（`packageRelease` 单任务）。
- **真机安装被 MIUI 挡住**：`INSTALL_FAILED_USER_RESTRICTED`，`settings put global adb_install_need_confirm 0` 无效，必须手动开「开发者选项 → USB 安装」。设备当前无任何 podroid/docklet 包（debug 已卸载）。release 包的装机冒烟**未做**，但 debug 包已端到端验证过同一份代码。
- 设备上 `com.dockerroid` / `com.midsancode.docklet` 都已不存在。
